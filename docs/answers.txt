8.
(I) Inheritance: When a new class is built from an existing class and
automatically gets its variables and functions. The child class can reuse
them and add its own. In this repo, Bicycle inherits from Vehicle and adds
its own gear count, and Car inherits from PoweredVehicle and adds its
engine size.

(II) Polymorphism: When the same function call does different things
depending on what type of object it's called on. Vehicle has virtual
functions like mileageEstimate and toString, and Bicycle and Car override
them with their own versions, so the right one runs depending on the
actual object.

(III) Encapsulation: Keeping a class's data private and only letting other
code access it through public functions. In Vehicle, myBrand and myModel
are private and can only be changed through getBrand, setBrand, getModel
and setModel. Bicycle and Car do the same thing with their own private
variables.

9. In the Integration Manager workflow there is one person called the
integration manager who pulls in changes from every developer's public repo
and merges them into the main repository. In the Dictator and Lieutenants
workflow there is an extra layer in between. Lieutenants are in charge of
specific parts of the project and merge their team's changes first, and then
the dictator only merges from the lieutenants into the main repo. So the
main difference is that Dictator and Lieutenants splits up the merging work
into levels instead of one person handling everything.

10. With 100 developers in a Centralized workflow, everyone pushes to the
same shared repo, so there would be a lot of conflicts and people constantly
having to pull and merge before they can push. It would also be hard to
review everything that goes in. With Dictator and Lieutenants, the work is
split up by area, so each lieutenant only reviews and merges changes for
their part of the project. That way the dictator doesn't get overwhelmed,
the code gets reviewed before it reaches the main repo, and the project
stays organized even with a lot of people.
